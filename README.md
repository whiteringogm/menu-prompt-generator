# menu-prompt-generator

毎日の食事予定、済／未、使い切り食材、今週の候補、願望、回避情報を入力し、AI相談用テキストを生成するPWAです。

## 主な機能

- 日付ごとの下書き保存
- 朝・昼・夕・間食の済／未管理
- 食材・希望の登録口を一つに統合
- 登録済み項目の区分をその場で変更
- 「期限注意」は≡の長押しで手動並び替え（冷蔵品と冷凍品の中でそれぞれ並び替え）
- 「期限注意」「今週の候補」の操作ボタンを1行に統一（≡ → ❄️チェック → 今日だけ除外 → ✏️編集 → 🗑️削除）。≡を押しやすく強調。「今日は使わない」は「今日除外」に短縮。区分移動で古いドラッグボタンが残らないよう修正
- 「期限注意」「今週の候補」に冷凍チェックを追加。新規登録時のチェック状態を登録前に取得し、冷凍を選択でき、デフォルトOFF（冷蔵）。冷凍品は区分内で冷蔵品より下に並び、相談文には「（冷凍）」と表示
- 期限注意の並び順・冷凍指定をローカルに保存し、全体JSONバックアップにも含める
- 「今日は使わない」の一日限定除外
- 翌日への自動引き継ぎ（今日中は除外、一日限定除外は解除）
- 登録済み項目、いつものメニュー、常備在庫表の編集
- 賞味期限ストックのコピペ一括同期（タグ任意・日付／年月の両対応・重複や削除差分の確認）
- 期限が14日以内のストックは期限注意、15〜45日以内は参考候補としてAI相談文へ表示。期限が先のものは非表示
- 期限ストックは独立して保存。普段の買い物・今週の候補・常備在庫への食品タグ入力は不要
- AI相談文生成・コピー
- 確定メニュー履歴と昨日の食事表示
- 全体／月別JSONバックアップ
- PWA・オフライン対応

## 期限ストックの一括同期

期限管理側で作成した全件一覧を「賞味期限ストック（一括同期）」に貼り付け、差分（追加・変更・削除）を確認して同期します。端末のlocalStorageに保存され、公開リポジトリやGitHub Pagesへ自動送信されません。全体JSONバックアップに含まれ、旧バックアップの読み込みでは既存の期限ストックを保持します。月別バックアップには含めません。

入力は `YYYY-MM(-DD) | タグ | 商品名 | 数量` 形式。タグは任意（間食／飲料／主食／おかず／食事の素／料理素材／製菓材料）、省略するとタグなしで登録します。年月のみの期限は年月表示を保持し、日数の判定だけ月末を使用します。同じ商品でも期限が違えば別品として保持します。**同期は貼り付けた一覧で置き換えるため、全件を貼り付けてください。**

テスト：`node --test expiry-core.test.js`

期限ストックを同期すると、「AI相談用テキスト」の `【期限注意】` と `【今週の候補】` の間に自動連携枠が挿入されます。出力する件数は相談文の上の行に表示され、同期後は保存件数と完了メッセージが確認できます。表示対象がない場合は連携枠を省略します。「AIへの指示文」の編集欄そのものには商品一覧を挿入しません。

## 期限ストック表示の検証

v5.1.24では、古い画面整形処理があとから初期化されても期限ストックの本文差し込みが有効になるよう、生成テキスト欄自身に処理を固定しています。件数表示は「対象」と「本文に実際に表示」の両方を確認でき、差があれば警告します。保存済みのリストを再貼り付けする必要はありません。表示が古い場合はPWAを再読み込みしてください。

テスト：`node --test expiry-core.test.js expiry-output.test.js`

### 数量の自由記述（v5.1.25）

期限ストックの数量欄は計算用の数値ではなく、在庫の説明として扱います。`1人前×2`、`小袋6個`、`1袋51g`、`固形80g×4`、`残り約半袋` などをそのまま保存・表示します。前後の空白を除き、数量の文言は保持します。数量を省略した場合は従来どおり `1個`。区切りの `|` と改行は数量欄に含められません。期限・品名・重複チェックは従来どおりです。
